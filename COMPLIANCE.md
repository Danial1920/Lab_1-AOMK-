# Соответствие требованиям

## Компонентная модель

- A–E, две реализации Lab1 и Lab2 имеют отдельные CID/фабрики и создаются через Eco Interface Bus.
- Lab1 включает C; C включает A и D; D включает B. Публичные операции вызывают дочерние интерфейсы.
- E агрегирует B и выдаёт X/Y. Lab2 агрегирует Lab1 и включает E; его Y-фасад вызывает E.
- Агрегирующий клиент запрашивает `IID_IEcoUnknown`. Фабрика отклоняет `outer != NULL` с другим IID.
- Внутренний неделегирующий unknown владеет временем жизни агрегированной части. Внешний объект освобождает его через интерфейс `Release`; concrete destroy-вызовы между компонентами отсутствуют.
- Публичные QI/AddRef/Release агрегированной части делегируют controlling unknown. Поддерживаемые интерфейсы имеют общую identity и доступны друг из друга.
- Включённые объекты сохраняют отдельную identity; владелец освобождает их ссылки до system/allocator.
- Численные и status/out-методы возвращают `int16_t`; калькуляторные операции возвращают `double`, AddRef/Release — `uint32_t`.

## Контракты и память

QueryInterface проверяет `me/riid/ppv` и обнуляет выход до запроса. Неизвестный IID возвращает ошибку. TryDivision обнуляет результат и сообщает о делении на ноль. Память, Copy и Fill используются через IEcoMemoryAllocator1. Ошибочные пути фабрик освобождают частично созданный граф; тесты проверяют баланс выделений, отказ allocator и неизвестные IID.

Новые double-интерфейсы имеют собственные IID и описаны в `SharedFiles/EcoLab2.idl`. Архитектура D/E следует материалам InsideACOM; бинарная совместимость с целочисленными учебными интерфейсами не заявляется.

## Сборка и проверки

| Проверка | Команда / свидетельство |
|---|---|
| Host + строгий C89 + отсутствие libc + sanitizer | `make ECO_FRAMEWORK="$ECO_FRAMEWORK" check` |
| Интеграция с настоящим Framework | `make ECO_FRAMEWORK="$ECO_FRAMEWORK" eco-test` |
| Статические Xcode-конфигурации | Команды Debug/Release в README |
| Восемь динамических фабрик и официальный loader | `CONFIGURATION=Debug/Release DesignFiles/Report/build_dynamic_runtime_macos.sh` |
| Динамические зависимости | `nm -u`, `otool -L` для каждой dylib; логи в BuildFiles/DynamicRuntimeLogs |
| Отсутствие статической подмены Dynamic | Runtime-клиент линкует только Framework; пустой runtime возвращает ненулевой код |
| Независимые численные эталоны | MATLAB/SciPy scripts и сохранённый вывод в DesignFiles/Reference |

Численный и компонентный код проверяется с `-std=c89 -fno-stack-protector -fno-builtin`. Стандартные заголовки/вызовы libc запрещены в компоненте; у консольных клиентов и официальных системных библиотек могут быть зависимости от libc. На macOS `libSystem` является платформенной зависимостью dylib; отсутствие собственных обращений проверяется через `nm -u`.

Linux/Windows/EcoOS source lists обновлены. Их полноценные сборки и Linux readelf не выдаются за результаты macOS. `make matrix` без официального кросс-компилятора сообщает SKIPPED. Официальной Eco.StdIO.C89 arm64 в архиве нет, поэтому вывод консольных клиентов использует stdio; StdIOShim в компонент не добавлен.
