# Соответствие требованиям ЛР2

Текущая архитектура и команды приведены в [README](README.md).

| Требование | Реализация и проверка |
|---|---|
| Учебные контракты X/Y | Официальные IID, int16-аргументы, int32 Addition/Multiplication; неизменённые внешние заголовки клиента |
| Взаимозаменяемость A/C | Одинаковый официальный CID; независимая C; один объект клиента, отдельные архивы A/C |
| Включение | Lab1 включает E (резерв D); D включает B (резерв A/C); Lab2 включает A/C и D для Horner |
| Агрегирование | Lab2 → Lab1 → B и E → B; приватные unknown, единый публичный controlling unknown |
| Получение интерфейсов | Настоящие factory/Interface Bus, полные матрицы QI для семи CID в каждом A/C-запуске |
| Владение | System/allocator удерживаются; дочерние ссылки освобождаются до них; ранний Release корня проверен |
| Отказы и память | NULL, неизвестный IID, некорректная агрегация, отказ Alloc; 267/267/live 0 в каждом варианте |
| Безопасное деление | Отдельный IEcoCalculatorSafe, ошибки 1101/1102, выход обнулён; Y не расширен |
| Сохранение Lab1 | Численное ядро не менялось, оба CID и все polyfit-контракты сохранены; регрессионные тесты |
| Изолированная поставка | Восемь архивов, по семь подключены к одному клиенту; Debug и Release |
| Dynamic | Семь CID-файлов на запуск, официальный loader; все 4 конфигурации Debug/Release × A/C |
| Честность тестов | Реальные операции и независимые ожидания; мутация операции даёт ненулевой код; пустой runtime отклонён |

Команды: `make check`, `make eco-test-variants`, `CONFIGURATION=Release make component-clients`, `make validation-build`; везде задаётся действительный `ECO_FRAMEWORK`. Логи проверки от 28 октября 2026 — `DesignFiles/Review/Verification_2026-10-28`.

Компоненты проверены с C89, без stack protector и встроенных libc-вызовов; память/Copy/Fill — через allocator. `nm -u` проверяет собственные ссылки, `otool -L` — зависимости dylib. Платформенная libSystem допустима; консольные клиенты используют stdio, отсутствующая официальная Eco.StdIO.C89 arm64 не подменена в компоненте.

У численного API сохраняется ограничение точности long: непредставимые точно значения отклоняются с 1005 и нулевыми коэффициентами. Horner ограничен int16-входами калькуляторов, последний результат — int32. Linux/Windows/EcoOS не проверены бинарной сборкой; `make matrix` без официального ECO_TOOLCHAIN сообщает SKIPPED. Оценку выставляет преподаватель; результаты тестов не являются гарантией балла.
